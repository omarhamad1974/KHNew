# KHIP website

**Start with [MANUAL.md](MANUAL.md)**: setup, hosting and daily use. This file is the feature reference.

Static site (HTML + Tailwind CDN). All content lives in `app-data.json` (English) and `app-data.ar.json` (Arabic) in the GitHub repository. There is no database, no sign-in and no client portal: the only thing that needs a login is the admin page, and it uses a GitHub token.

## Day to day: `admin.html`

Open `https://YOUR-SITE/admin.html`, sign in with a GitHub fine-grained token (Contents: read and write, for this repository only), and edit. The admin has two places, and English and Arabic are written **side by side** everywhere (English left, Arabic right; an empty Arabic box means "show the English").

- **General**: the things that belong to the whole site. Pages: **Brand & logos**, **Contact & social**, **Languages & words** (site languages, WhatsApp suggestions, news categories and all short words of the site), **Colors** (the palette and the section width), **Fonts**, **Header, bar & menu**, **Cards**, **Text alignment**, **Picture effects**, **Animation**, **Map & logo motion**.
- **Sections**: pick a page (Home, About, Patents, Trademarks, Translation), then a section in the order it appears. Each section has its **fixed texts**, its **lists** (slides with hero height and controls, countries, services, articles with Import, client quotes, team) and its **FAQ**, then **Look of this section** (background, cards, fonts, text alignment, photo effect, animation).
- **Import**: articles from Word / Markdown (Sections, Home, Latest news) and hero slides from Word / Markdown / spreadsheet (Sections, Home, Slider). Word: a **Heading 1** per item, then `Subtitle:` and `Tag:` lines and the picture. Markdown: `# Title` plus the same lines (`Image: photo.jpg`). Spreadsheet: columns `Title, Subtitle, Tag, Image`. You review, then add at the end / top or replace.
- **FAQ** is stored as `faq` in `app-data.json`: `{ "title": "", "intro": "", "pages": { "patents": { "hidden": false, "title": "", "intro": "", "items": [ { "id": "1", "q": "Question", "a": "Answer" } ] } } }`.
- Text boxes support `**bold**`, `## subtitle` and `- bullet` (use the B, H and list buttons).
- Photos: upload from your device (large photos are shrunk automatically) or pick one already in `assets/`.
- Add, duplicate, reorder, delete, search (long lists), Ctrl+S to save, undo arrow to discard changes, download icon for a backup.

## Live preview (admin: Preview button)
The **Preview** button shows the real page with your unsaved changes (phone, tablet or desktop width; English or Arabic) beside the editor, scrolled to and outlining the section you are editing. See [CONTROL-PLAN.md](CONTROL-PLAN.md), phase 1. `preview.js` is loaded first by every public page and does nothing unless the page is inside the admin preview (address `?khip-preview=1` and a parent window that is `admin.html`); `admin-preview.js` is the panel.


## Video sections (admin: Sections, Home, Video / About, Video)
A YouTube video with an optional title and text, on the **Home** page and on the **About** page. Paste any YouTube address (`watch?v=`, `youtu.be/`, `/shorts/`, `/live/` or the 11-letter id; a start time such as `?t=90` is kept). The admin shows the video it found. The page shows a poster with a play button and loads the YouTube player (youtube-nocookie.com) only when it is pressed, so the page stays fast.
- **Hide this video section** keeps everything but shows nothing. Nothing shows either while the English link is empty.
- **Arabic**: the Arabic boxes can hold a different (Arabic) video, title and text; an empty box shows the English one.
- **Position** (a list in the admin). Home: right under the slider (start), or after any other section. About: after the first paragraph (start), after the second paragraph, or after any other section. Between two paragraphs the video sits inside the About text; elsewhere it is a full section.
- **Text and video**: text beside, above or below the video. With no title and no text the video is shown alone, wide.
- **Look of this section** works as for every section (background, header parts, fonts, alignment, animation).
- **Button** (optional): words (English and Arabic) plus a link: `whatsapp` (a chat with the number in General, Contact), a web address, `tel:+20...`, `mailto:...` or a page of the site (`about.html#team`). Both must be set for it to show.
- **Cover picture** (optional): upload or pick from `assets/`; it is cropped 16:9. Empty: YouTube's own picture.
- **Start by itself**: silent, looping, starts when half the video is in view and pauses when it scrolls away; visitors can switch the sound on. Visitors whose device asks for less motion, or who save data, get the play button instead.
- **Search engines**: the build (`scripts/build-seo.js`) writes VideoObject data (title, text, picture, YouTube address, and the publish date if you fill *Date the video was published*) and a copy of the title and text for crawlers that do not run scripts.
- Saved as `videos` in `app-data.json`: `{ "home": { "url": "", "title": "", "text": "", "layout": "side|top|bottom", "after": "home-hero", "hidden": false, "poster": "", "autoplay": false, "date": "2025-03-02", "ctaText": "", "ctaLink": "whatsapp" }, "about": { ... "after": "p1" } }`; Arabic `url`, `title`, `text`, `ctaText` in `app-data.ar.json`. New file: `video.js`.

## Section header (admin: Sections, Look of this section, Section header)
Hide or show the **title**, the **icon**, the **thin line** under the title and, on the Patents / Trademarks / Translation pages, the **WhatsApp button** of any section. A hidden title is only visually hidden (search engines and screen readers still read it). Saved as `theme.secHead` (`{ "<section>": { "title": true } }`, only hidden parts are written). See [CONTROL-PLAN.md](CONTROL-PLAN.md), phase 2.

## Columns per row (admin: Sections, Look of this section, Columns per row)
Set how many cards sit side by side (1 to 4) on **tablet** and **desktop** for Home Services, Home Latest news, About Advantages, About Our team and the Details cards of the service pages. Phones are not affected. Saved as `theme.cols` (`{ "<section>": { "t": "2", "d": "3" } }`). See [CONTROL-PLAN.md](CONTROL-PLAN.md), phase 3.

## Card backgrounds (admin: Sections, open the item, Card background)
A colour and/or a picture for one card: a news article, a team member, the Translation card, the IP Services card (Home, Services). With a picture you can darken it and choose the text colour. Saved on the item as `cardBg`, `cardImage`, `cardShade`, `cardText` (and on `ipCard`). See [CONTROL-PLAN.md](CONTROL-PLAN.md).

## Picture sizes
Uploading a slider, news or team picture in the admin also uploads smaller copies (`-w480`, `-w960`) and lists them in `imgSizes`; the pages use `srcset` so phones load the light copy. Older pictures are unchanged.

## Phone editor
On a phone the English and Arabic boxes are shown one language at a time: use **Show: English | عربي | Both** under the tabs. Wider screens show both side by side.

## Fonts (admin: General, Fonts; Sections, Look of this section, Fonts)
Choose the letters of the site: **Headings** (titles, card titles, FAQ questions) and **Text** (everything else), separately for **English** and **Arabic**, for the whole site and for a single section. Each box offers ready fonts (16 Latin, 8 Arabic), **the visitor's own font (system)** and **Another Google font** (type its exact name from fonts.google.com). The first choice of every box keeps the original fonts (Cormorant Garamond and Jost for English, Noto Naskh Arabic and Cairo for Arabic). A section left on "Same as the whole site" follows General. The preview shows English and Arabic samples. Visitors download only the fonts you chose. Logos, the KHIP word mark and icons are not affected.
Saved as `theme.fonts`: `{ "all": { "head": { "en": "Playfair Display", "ar": "Amiri" }, "body": { "en": "Inter", "ar": "Tajawal" } }, "sec": { "<section>": { "head": { "en": "Lora" } } } }`. `theme.js` sets four CSS variables (`--fh-en`, `--fh-ar`, `--fb-en`, `--fb-ar`; a section's own values sit on its element) and loads the Google stylesheet; `styles.css` and `tailwind-config.js` read `--fh` / `--fb`, which follow the page direction.

## Look controls (admin: General and Sections)
Since admin restructure phase 3 there are no separate Look tabs. **Site-wide** settings are pages of **General**: Colors, Fonts, Header, bar & menu (header, bottom bar, WhatsApp box, menu), Cards, Text alignment, Picture effects, Animation, Map & logo motion, Brand & logos. The look of **one section** (background, cards, fonts, text alignment, photo effect, animation) is in **Sections**: pick the page and the section, then open **Look of this section**. A palette icon on a section's button shows that it has its own look; **Reset this section** removes it. Wherever a section leaves a setting on its default it follows General. The descriptions below still apply; read "tab" as "page of General" or "Look of this section".
Everything below is saved under `theme` in `app-data.json`. Nothing changes on the site until you pick something; **Reset** buttons go back to the original look. Colours can be picked from the site palette, from your own colours (General, Colors) or as any colour.
- **Header & bar** (phase 1): header background (with opacity), header text / menu / icon colour (automatic light text on dark backgrounds), the line under the header; bottom bar background and button colours; the **WhatsApp text box**: background (with opacity), typed text, hint text and icon, outline, send button and send icon.
- **Cards** (phase 1): background (with opacity), text, titles and border of every card (service, news, team, FAQ, quote frame, contact tiles), and the same per section ("Cards in one section"; anything left on *Same as all cards* follows the page-wide settings).
- **Text alignment** (phase 2): for the whole site and for each section, choose start, center, end or justify, separately on phone (under 640 px), tablet (640 to 1023 px) and desktop (1024 px and up). Headings never stretch (with Justify they line up at the start); buttons, icons and photos keep their place. Start and end follow the reading direction, so Arabic flips correctly. Saved as `theme.align` (`all`, and `sec` per section).
- **Logos** (phase 2): the header logo (all pages), the home page logo and the About page logo. For each: replace the picture (upload or pick from `assets/`; a PNG with a transparent background is best) and set its width in pixels for phone, tablet and desktop, with quick sizes S / M / L / XL and an **Original** reset. Saved as `theme.logos` (`header`, `home`, `about`, each with `image`, `m`, `t`, `d`).
- **Menu** (phase 3): choose the layout. **Default**: links in the header on large screens plus the bottom bar (as before). **Bottom bar only**: no links in the header. **Bottom bar and sandwich**: a round three-line button in the header opens a side menu (Home, About, Jurisdictions, Services with Patents / Trademarks / Translation, News) on every screen size. For the side menu you can pick the side (start or end; it flips in Arabic), the panel background and text colour (default: the bottom bar colours), how much the page behind darkens, the panel width, and whether the header keeps its links on large screens. It closes with the X, the dark area, Escape, or after choosing a link. Saved as `theme.menu` (`mode`, `side`, `keepNav`, `bg`, `text`, `overlay`, `width`); the behaviour lives in `look.js`.
- **Image effects** (phase 4): for all pictures, and separately for the home slider, news pictures, team photos and section background photos: **opacity** (0 to 100%) and a **color filter** (a site color, one of your own colors, or any color) with an **intensity** (0 to 100%; 35% when you pick a color and do not move the slider). Each group can follow "All pictures" or have its own; a section that uses a photo background can also get its own effect. The slider pictures start at 80% opacity as before. Section photos fade into the color behind them, and the existing darkening slider (Sections, Look of this section, Background) still works on top. Saved as `theme.imgfx` (`all`, `hero`, `news`, `team`, `sections`, `sec` per section). Pictures keep their own look until something is set.
- **Animation of cards and text** (phase 5): for all sections and for each section, separately for **cards** (services, news, FAQ, team, contact tiles) and **text** (titles and paragraphs outside cards): effect (rise, drop, slide in from the start or end, fade, zoom in or out, flip, come into focus, none), distance, feel (smooth, soft, snappy, bounce, even), speed, delay, delay between neighbours (stagger), and whether it plays once or every time it scrolls into view. Cards also get a pointing effect: lift, grow, glow or none. A section with no effect set keeps the original fade-up. Visitors whose device asks for less motion see everything at once. Saved as `theme.anim` (`all` and `sec`, each with `cards` and `text`); the behaviour lives in `look.js`.
- **Animation of the map and logos** (phase 6): **Map**: how it appears when it scrolls into view (countries fade, pop or rise in one after another, optionally with the rest of the map), constant movement of the highlighted countries (breathe, or a wave of light), what happens when pointing at a country (glow, grow, raise), and the pulse around the offices (none, slow, fast, wide, any color). **Logos** (header, home, About; set for all and override per logo): entrance effect, distance, speed, delay, constant movement (float, breathe, sway, glow) and a pointing effect (grow, tilt, lift, glow). Visitors whose device asks for less motion get no automatic movement. Saved as `theme.motion` (`map`, `logos`); the behaviour lives in `look.js`.
- All six Look phases are done; the plan is kept in [LOOK-PLAN.md](LOOK-PLAN.md). The admin restructure (General, Sections, Fonts) is in [ADMIN-PLAN.md](ADMIN-PLAN.md).

## Arabic (right-to-left) site
Files: `lang.js` (language engine), `pages-i18n.js` (fixed texts of the pages, English and built-in Arabic), `app-data.ar.json` (the Arabic content, same structure as `app-data.json`), plus `index.html`, the four inner pages, `faq.js`, `service-page.js`, `footer.js`, `styles.css`, `rich.js` and `admin.html`.
- **Choose the languages:** admin, General, Languages & words, **Site languages**: English only, Arabic only, or both. With both, a button in the header (العربية / English) lets visitors switch on every page; their choice is remembered. Save to GitHub to apply.
- **Write the Arabic content:** every box in the admin has the English on the left and the Arabic on the right; there is no language switch. Leave an Arabic box empty and the Arabic site shows the English text for it, so nothing is ever blank. Images, dates, icons and ids are shared. News categories are translated in the same order as the English list. Save writes only the file(s) that changed (`app-data.json`, `app-data.ar.json`).
- **Words and fixed texts:** the short words of the site (menu, buttons, headings) are in General, Languages & words; the fixed wording of each section is in Sections. Built-in English and Arabic wording is shown in grey; type your own to replace it.
- **FAQ:** add, remove and reorder questions in English; in Arabic mode write the Arabic question and answer for each.
- A page with a service text left empty in Arabic shows the English text of that service.

## Services on the home page
Two main cards, centred: **IP Services** (every service except Translation, e.g. Patents and Trademarks, shown as buttons that open the pop-up) and **Translation** (the service whose page is `translation.html`). The same grouping builds the header **Services** drop-down. The home slider's arrows, dots and pause button are off unless ticked in admin, Carousel tab, "Slider controls".

## Services: three editable parts
In admin, Services tab, each service has three text parts (Patents, Trademarks and Translation are filled in already):
1. **Brief**: the short text on the home page card (also the top of the pop-up).
2. **Pop-up content**: the extra information in the pop-up that opens from the home page card or from the About page cards.
3. **Dedicated page content**: the text of the full page (`patents.html`, `trademarks.html`, `translation.html`). Text before the first `## ` line is the introduction; each `## Heading` becomes a card. Leave it empty to keep the text written in the page itself.
The **Dedicated page file** field (for example `patents.html`) connects a service to its page and shows the "More information" button.

## Site navigation (bottom bar)
Home, IP Services (IP Services section), News (Latest news section), Jurisdiction (Jurisdictions section), About (about.html). The round paper-plane Send button sits inside the WhatsApp text box.


## Version stamp and fresh pictures (`site-version.js`)
- A small dark box in the bottom-left corner of every public page shows the build name and when `app-data.json` was last fetched from GitHub (plus the file's saved time). Tap it to shrink; `?debug=0` hides it, `?debug=1` shows it again. Set `STAMP=false` in `site-version.js` to remove it for good.
- All site pictures are requested as `picture.jpg?v=2`. To force a re-download for everyone, raise `IMG_V` in `site-version.js` and change `?v=2` in the logo tags of the HTML pages.

## Search engines and Arabic addresses (`scripts/build-seo.js`)
The pages fill themselves from `app-data.json` with JavaScript, which many crawlers do not run. The SEO build writes what they need straight into the HTML. Run it with `node scripts/build-seo.js`; on GitHub it runs by itself after every change to the content or the pages (`.github/workflows/build-seo.yml`, which commits the result; it needs Settings, Actions, General, Workflow permissions, **Read and write**).
- **Head of every page**: description, canonical address, Open Graph / Twitter tags, `LegalService` structured data (name, phone, e-mail, map position, countries served, social links) and, where the page has FAQ, the FAQPage data.
- **Crawlable text**: a hidden `<h1>` on the home page and a `<noscript>` copy of the page text (about text, services, countries, news, testimonials, team, FAQ, contact). Visitors with JavaScript never see it.
- **Arabic at its own address**: when the site languages are **both**, the build writes `index-ar.html`, `about-ar.html`, `patents-ar.html`, `trademarks-ar.html`, `translation-ar.html` (Arabic title, description, `lang="ar" dir="rtl"`, `hreflang` links between the two versions). The EN | AR button goes to the other address, links on an Arabic page stay on Arabic pages, and an old `index.html?lang=ar` link is sent to `index-ar.html`. Do not edit the `-ar` files: they are rebuilt from the English pages. Text that is still English in `app-data.ar.json` (country summaries, news) is left out of the Arabic page's crawlable copy.
- **`sitemap.xml` and `robots.txt`** (with the English and Arabic address of each page).
- **Settings** in `app-data.json`, block `seo` (all optional, checked by `scripts/validate.js`): `siteUrl` (the live address, **needed** for canonical, hreflang, sitemap and the share picture; it is never guessed), `name`, `ogImage` (a file in `assets/`, default `assets/khip-logo.jpg`) and `pages.<home|about|patents|trademarks|translation>.title|description.<en|ar>` to replace the built-in titles and descriptions. The Arabic descriptions built in are drafts: have them reviewed with the rest of the Arabic.
- **How the language is chosen**: when a page carries `data-khip-lang` (written by the build for English + Arabic sites) the address decides the language. Without it, and inside the admin preview, the old behaviour (saved choice, `?lang=`) is used.
- Files: `scripts/build-seo.js`, `lang.js` (`KLang.page()`, `KLang.url()`, `KLang.links()`), `footer.js`, `look.js` and `service-page.js` (they read the page name through `KLang.page()` so `about-ar.html` counts as About).

## Checks

`node scripts/validate.js` checks `app-data.json` (required fields, duplicate ids, missing images, bad links). GitHub runs it on every push (`.github/workflows/validate.yml`).

## Notes
- **Tailwind is compiled, not loaded from the CDN.** On GitHub, the same Action that builds the SEO pages (`.github/workflows/build-seo.yml`) runs `scripts/build-tailwind.js`: it builds `tailwind.css` (only the classes the site uses, minified) and points the five public pages at it, so visitors no longer download Tailwind's script and the browser no longer builds the styles on every page view. The theme still comes from `tailwind-config.js`. If the build fails for any reason, the pages go back to the CDN by themselves and the old `tailwind.css` is deleted, so styles are never lost. Each page has two marked places in its `<head>` (`KHIP-TW-JS` and `KHIP-TW-CSS`); do not remove them. To go back to the CDN on purpose run `node scripts/build-tailwind.js --cdn`; `--check` tells which one is active. `admin.html` keeps the CDN. When you add a **new** Tailwind class in a page or script nothing else is needed: the next push rebuilds. Classes written only inside `app-data.json` are not seen (the site does not use any).
- Contact phones, emails, address, map, WhatsApp number and social links: admin, General, Contact & social (stored as `contact` and `social`; `contact.js` puts them on the pages). ## Importing articles (admin, Sections, Home, Latest news, Import)
Add many articles in one go from Word or Markdown files.
1. Admin > News > **Import**, then choose one or more files (you can also drop them). Accepted: `.docx`, `.md`, `.txt`, a `.zip` with the files and pictures, and picture files chosen together with a `.md` file.
2. **Word**: each article starts with a title in the **Heading 1** style. Right under it, one detail per line: `Subtitle:`, `Date:`, `Category:`, `Excerpt:` (Arabic labels work too). Then the article text. The first picture of an article is its cover; other pictures stay inside the text. Heading 2, bold text and bullet lists are kept.
3. **Markdown**: each article starts with `# Title` (or a `---` front-matter block containing `title:`), followed by the same detail lines. Pictures: `Image: cover.jpg` or `![](photo.jpg)`, picked together with the `.md` file or placed in a `.zip`. `https://` picture addresses are used as they are. The Import window has a "Download a Markdown template" link.
4. Review the list (untick what you do not want, choose top or end of the news list), press **Import**, then **Save to GitHub**. Pictures are uploaded when you press Import; a cover is cropped to 2:1 like the normal upload.
- Dates: 2026-03-14, 14/03/2026 (day first) or 14 March 2026. Categories are matched to your list ignoring case; a new one is added to the list. No excerpt: the first paragraph is used. An article whose title already exists is unticked by default.
